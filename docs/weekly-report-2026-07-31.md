## 一、系统是怎么部署的

整个系统由三台"电脑"组成，各干各的活：

```
用户浏览器
    │
    ▼
┌─────────────────────────────┐
│  Vercel（前端）              │  展示网页、聊天界面、图表
│  免费，自动部署              │  
└─────────────┬───────────────┘
              │ 需要预测时，打电话问
              ▼
┌─────────────────────────────┐
│  Railway（预测引擎）         │  专门跑数学模型的 Python 服务器
│  免费额度 $5/月              │  Docker 容器部署
│  地址: intelligent-          │
│  imagination-production-    │
│  c26e.up.railway.app        │
└─────────────┬───────────────┘
              │ 需要数据时，去取
              ▼
┌─────────────────────────────┐
│  Neon（数据库）              │  存价格历史、用户信息
│  免费 PostgreSQL             │  
└─────────────────────────────┘
```

### Railway 上具体跑了什么

Railway 的预测服务是通过 **Docker 容器**部署的。简单理解，就是把整个运行环境打包成一个"快递箱"，Railway 拿到箱子直接启动就行。

**Docker 箱子里装了什么：**

| 组件 | 用途 |
|------|------|
| Python 3.11 | 编程语言 |
| Flask（Web 框架） | 接收网页发来的请求："帮我预测硫磺下周价格" |
| ARIMA + XGBoost | 两个传统预测模型，一个看趋势一个看细节 |
| PatchTST | 深度学习 Transformer 模型（本周代码写了但 Railway 内存不够跑） |
| scikit-learn / numpy / pandas | 数学计算工具 |
| 外部数据抓取器 | 自动从美联储 FRED 拉取油价、汇率、天然气价格 |
| 生意社爬虫 | 从 100ppi.com 抓硫磺/钾肥/尿素现货价格 |
| gunicorn（生产服务器） | 让服务稳定运行，崩溃了自动重启 |

**Railway 的 Dockerfile（部署说明书）：**

1. 基于 Python 3.11 官方精简镜像
2. 安装 C++ 编译器（某些数学库需要）
3. 安装 14 个 Python 依赖包
4. 复制预测代码（app.py + external_data.py）
5. 以单进程模式启动（免费版内存有限）

### 备选方案

| 方案 | 状态 | 用途 |
|------|------|------|
| **Render** | 配置保留，可一键切换 | 如果 Railway 出问题，切到 Render |
| **Docker 自部署** | 准备了国内镜像版 | 企业内网部署，用清华源下载依赖 |
| **Zeabur** | 配置保留 | 国内可直连，无需翻墙 |

## 二、本周具体修改了什么

### 修改清单

#### 文件 1：`python-service/app.py`（Python 预测引擎，+85 行）
**这是改动最大的文件，所有预测逻辑都在这里。**

**修复 4 个历史 Bug：**
- 硫磺模拟数据错误：9000 元/吨 → 900 元/吨（之前小数点差了一位）
- 趋势措辞错误：价格在跌却说"涨幅"，改为自动判断"上涨"/"下跌"
- 数据库读取的数字类型错误（Decimal 未转 float）
- 中期趋势（30 天）的参数写了但从来没用，补入分析文本

**修复预测引擎崩溃（3 个连环 Bug）：**
- **Bug A**：3 个 API 接口的错误处理代码写反了——初始化步骤在"安全网"外面，出错了直接崩，不返回有意义的信息
- **Bug B**：模型训练时用了 6 个维度（3 个价格特征 + 3 个经济因子），但测试评估时只给了 3 个维度，模型说"信息不够，算不了"，直接报错
- **Bug C**：模型文件加载后，特征数可能和训练时不匹配（旧模型 vs 新代码），加了一致性校验，不匹配就自动重新训练

**多品种支持：**
- 之前：无论查硫磺、钾肥、尿素还是磷矿石，全返回同一份数据
- 现在：每个品种独立加载数据、独立保存模型、切换品种自动切模型
- 模拟数据也按品种生成不同的价格区间（硫磺 900、磷矿石 1130、钾肥 3570、尿素 1810）

---

#### 文件 2：`python-service/external_data.py`（外部经济因子抓取，~255 行，新文件）

功能：自动从美联储 FRED 数据库拉取三个经济指标——
- WTI 原油价格（硫磺是炼油副产品）
- 美元指数（大宗商品以美元计价）
- 天然气价格（硫磺生产用天然气）

数据缓存 24 小时，不频繁请求外部 API。这些数据最终并入了 XGBoost 模型的特征输入。

---

#### 文件 3：`python-service/Dockerfile`（Railway 部署说明书）
 从 `COPY python-service/app.py .` 扩展为同时复制 `external_data.py`，否则 Railway 容器里找不到这个文件。

最终版本做的事：
1. Python 3.11 基础镜像
2. 安装 gcc/g++ 编译工具 + 数学运行时库
3. pip 安装 14 个依赖
4. 复制 app.py + external_data.py
5. 创建 data 和 models 目录
6. 单 worker 启动 gunicorn（免费版内存限制）

---

#### 文件 4：`python-service/requirements.txt`（Python 依赖清单）
本周新增了 3 个依赖：
- `torch>=2.0.0`（深度学习框架，~200MB，Railway 免费版空间不够所以实际没跑起来）
- `transformers>=4.40.0`（HuggingFace 模型库，PatchTST Transformer 用）
- `psycopg2-binary>=2.9`（连接 PostgreSQL 数据库用）

---

#### 文件 5：`src/lib/commodity-scraper.ts`（TypeScript 数据爬虫，+15 行）
**7/27 之前修复（生意社 JS 验证绕过），本周做了 2 个补充修复：**

**修复 1 — cheerio 类型错误：** 遍历表格的变量类型标注用了错误的类型名，TypeScript 编译器把它推断为"无解的类型"，编译失败。改为显式类型断言。

**修复 2 — BDI 指数降级：** BDI（波罗的海航运指数）从新浪财经 API 拉取失败时，之前返回空数据。改为返回基于历史规律的模拟数据，至少图不会空着。

---

#### 文件 6：`src/services/transformer-prediction.ts`（Transformer 预测客户端，+16 行）
**修复置信度 NaN 问题：**

Python 预测服务返回的置信度是中文"高"/"中"/"低"，前端直接用数学函数处理中文 → 结果是 NaN（不是数字）。加了转换：高=90%，中=75%，低=60%。

同时修了一个语法错误（变量声明写在了对象属性赋值的位置）。

---

#### 文件 7：`src/app/api/cron/ingest-commodity-data/route.ts`（定时数据入库，-17 行）
**移除了有问题的通知入库代码：**

价格大幅波动时，系统会自动发通知提醒。但通知写入数据库的代码有两个致命错误——缺用户 ID 字段、ID 字段类型不匹配。每次触发就直接报错。改为输出控制台日志，不写数据库。

---

#### 文件 8：`tsconfig.json`（TypeScript 编译配置，2 行）
**修复编译报错：** 一个辅助脚本文件（`scripts/export-training-data.ts`）引用了不存在的第三方库，导致整个项目编译失败。把它从编译范围中排除。
