## 第一章：数据真实化 — 让每一分钱都有据可查

### 痛点

市面上的硫磺预测产品，价格数据是模拟生成的，精度指标是 `Math.random()` 算的。用户问"准不准"，没人敢回答。

### 我们怎么做的

**7 月：接入真实数据源**

| 改进项 | 之前 | 之后 |
|--------|------|------|
| 价格数据 | 模拟生成 | 直连**生意社**现货报价 |
| 品种覆盖 | 仅硫磺 | 硫磺/磷矿/钾肥/尿素 **4 品种** |
| 外部因子 | 写了没用 | 6 个经济因子（油价、汇率、天然气等）输入 XGBoost |
| 模型精度 | MAPE 8.81% | MAPE **7.69%** |

接入 6 个数据源：生意社、新浪财经、FRED（美联储）、Frankfurter（欧央行）、GDELT（全球新闻）、AKShare。

设计了 **L0→L4 五级降级链**保证数据不断线：

```
L0 实时主源 → L1 备用源 → L2 新鲜缓存 → L3 过期缓存 → L4 兜底值
```

统一工具 `fetchWithRetry`，所有响应带 `tier` 字段打标，数据来自哪一层一目了然。

**8 月中旬：精度体系去伪造（P0 级修复）**

发现精度面板"95%准确率"是假数据。完全重写，四级真实数据管道：

```
优先级1: Python 回测（ARIMA+XGBoost）
优先级2: 朴素基准回测（Next.js 原生）
优先级3: 企业预测记录
优先级4: 诚实空态（无数据就显示空态，绝不伪造）
```

当前朴素基准结果：MAE ¥92.59/吨，MAPE 1.00%，R² 0.356。部署 Python 服务后预计 R² > 0.8。

> **技术判断**：宁可展示不完美的真实，也不展示完美的虚假。这是我们对"可信"的定义。

## 第二章：MCP 服务 v0.3 — 最有战略价值的一步

### 为什么做 MCP

传统做法：用户打开网站 → 登录 → 找页面 → 看数据 → 自己分析。

**MCP 做法**：用户在 Claude Desktop 里问一句话 → AI 自动调用我们的实时数据、预测模型、知识图谱 → 返回分析结果。

> MCP = 给 AI 助手装上"数据插座"。API 是给系统用的，MCP 是给人用的。

这不是一个功能改进，是**交互范式的转变**——从"人适应系统"到"系统适应人"。

### MCP 是什么（给非技术听众）

您在用 Claude、DeepSeek 这些 AI 助手时，问它"今天硫磺多少钱一吨"，它只能凭训练时的旧知识猜。

**MCP（Model Context Protocol）** 是一个行业标准协议，让 AI 助手能够调用外部工具获取实时数据。我们做了一个 MCP Server，相当于在 AI 和我们的系统之间架了一座桥：

```
您在 AI 里提问
      ↓
AI 自动调用我们的 MCP 工具
      ↓
MCP Server 带 API Key 去我们系统取实时数据
      ↓
AI 拿到真实数据，用自然语言回答您
```

**您什么都不用做，像平时聊天一样提问。**

| 以前 | 现在 |
|------|------|
| 打开网站 → 登录 → 找页面 → 看数据 → 自己分析 | 问一句话 → AI 自动查数据+分析+给建议 |
| 人适应系统 | 系统适应人 |

### 做了什么

工具从 11 → **18 个**，覆盖六大能力：

| 分类 | 工具 | 能问什么 |

| **行情数据** | `get_prices` | "最近一周华东液硫价格走势？" |

| | `get_commodity_analysis` | "尿素行情怎么样？" |
| | `cross_commodity_analysis` | "硫磺和尿素对比一下？" |

### 架构决策（体现工程能力）

| 决策 | 原因 |
|------|------|
| **Stateless 模式** | 每请求新建实例，支持多客户端同时接入，解决 "Server already initialized" 问题 |
| **双传输 stdio + HTTP** | 本地用 Claude Desktop 走 stdio，远程部署走 HTTP，一套代码两种场景 |
| **DEMO 模式** | 无需 API Key 即可体验，降低试用门槛 |
| **向下兼容** | v0.2 的 11 个工具全部保留，零破坏性升级 |

### 解决的部署问题

| 问题 | 根因 | 解决 |
|------|------|------|
| Docker 生产环境 tsx 找不到 | 构建产物未包含 | 多阶段构建，`node dist/index.js` |
| Railway 容器反复重启 | `npx tsc` 每次重新编译 | `npm run build` 预编译 |
| 浏览器插件 CORS 失败 | 未配置跨域头 | 添加 CORS 响应头 |
| Windows 环境变量不生效 | 进程级 env 丢失 | 改用 `.env` 文件 |

### 安全设计

| 安全措施 | 说明 |
|----------|------|
| API Key 认证 | 每次请求必须携带有效密钥（AES-256-GCM 加密），无 Key 拿不到数据 |
| 密钥自助管理 | 网页控制台申请、可随时停用 |
| 私有化部署 | Docker 容器化，可部署在企业内网 |
| 配额控制 | 每次工具调用消耗 1 次配额，默认每月 1000 次免费 |

### MCP 与 API 的区别

| 对比 | API | MCP |
|------|-----|-----|
| **给谁用** | 系统（ERP、数据中台） | AI 助手（Claude、DeepSeek） |
| **调用方式** | 程序代码调用 | 自然语言对话 |
| **使用场景** | 系统集成、自动化流程 | 日常查询、分析决策 |
| **技术门槛** | 需要开发人员 | 业务人员也能用 |

> 一句话：API 是给"系统"用的，MCP 是给"人"用的（通过 AI 助手）。

### MCP 的战略意义

- **对采购经理**：从"人找信息"到"信息找人"，问一句话拿到数据+分析+建议
- **对销售**：AI 随时调取精度报告和客户案例，演示效率翻倍
- **对开发者**：MCP Server 从硫磺数据查询工具，升级为大宗原料多品种智能决策平台的基础设施
- **对行业**：企业软件的入口正在变成 AI 对话，我们提前铺好了路

### 接入方式

**方式 1：Claude Desktop 本地接入（推荐）**

1. 本地编译 MCP Server：`cd mcp-server && npm run build`
2. 打开 Claude Desktop → Settings → Developer → Edit Config
3. 添加配置：
   ```json
   {
     "mcpServers": {
       "sulfur-tracker-agent": {
         "command": "node",
         "args": ["D:\\市场方案agent\\sulfur-agent-web\\mcp-server\\dist\\index.js"],
         "env": {
           "API_BASE_URL": "https://sulfur-agent-web.vercel.app",
           "API_KEY": "sk_你的真实API_KEY",
           "INDUSTRY_CODE": "sulfur"
         }
       }
     }
   }
   ```
4. 完全退出 Claude Desktop 并重新打开
5. 输入框旁出现工具图标 → 接入成功

**方式 2：DEMO 模式零门槛体验**

```bash
cd mcp-server
DEMO_MODE=true MCP_TRANSPORT=http npm run mcp:http
```

无需 API Key，所有工具返回模拟数据供体验。

**方式 3：远程 HTTP 接入**

连接 Railway 部署的公网端点：`https://你的域名.up.railway.app/mcp`

覆盖百川资讯、卓创资讯、隆众资讯、生意社。
